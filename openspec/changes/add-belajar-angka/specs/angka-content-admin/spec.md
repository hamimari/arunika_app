## ADDED Requirements

### Requirement: Angka admin API
The backend SHALL expose, under `/admin/angka`:

**Objects:**
- list (with derived status and a "used in n levels" count);
- create a draft;
- read and save a draft;
- publish, hide, unhide and delete.

**Numbers:**
- list;
- save a draft;
- publish, hide, unhide, set-free and unset-free.

**Levels:**
- list (derived status, version and object names);
- create a draft with defaults, and read and save a draft;
- preview;
- list versions, publish and roll back;
- hide, unhide, set-free and unset-free;
- reorder (the full id list) and delete.

Draft reads and writes, creating, previewing and listing SHALL be open to any admin role. Every other write SHALL require the `publisher` role and respond 403 to editors.

Draft saves SHALL take `draft_rev` and respond `409 DRAFT_CONFLICT` when it is stale. Every write SHALL record an `admin_audit_log` entry (entity types `angka_object`, `angka_number` and `angka_level`) in the same transaction.

#### Scenario: Editor publishes
- **WHEN** an editor calls publish on Level 2
- **THEN** the server responds 403 and nothing changes

#### Scenario: Concurrent edits
- **WHEN** two editors save the same level draft with the same `draft_rev`
- **THEN** the second save responds 409 `DRAFT_CONFLICT`

#### Scenario: Rollback
- **WHEN** a publisher rolls Level 2 back to v1 while v3 is current
- **THEN** v4 is created with v1's content, and the draft becomes v1's content

#### Scenario: Free level moved
- **WHEN** a publisher sets Level 2 free while Level 1 is free
- **THEN** Level 2 is free, Level 1 is not, and both changes are audited

### Requirement: Angka publish validation
Publishing SHALL respond `422 {"code":"VALIDATION_FAILED","fields":[{path, code}]}` when any rule fails.

**Object:**
- `name` is 1–30 characters, and `question_text` is 1–80;
- it has an image and a question audio, each an asset of the right kind or an https URL;
- an uploaded image is at most 300 KB (`TOO_LARGE`) and does not have `has_alpha = false` (`NOT_TRANSPARENT`);
- an uploaded question audio is at most 5 seconds (`TOO_LONG`).

**Number:**
- `name` is 1–20 characters;
- it has an audio;
- its object is published and not hidden.

**Level:**
- `name` is 1–40 characters;
- `1 ≤ min ≤ max ≤ 20` and `5 ≤ question_count ≤ 20`;
- it has at least one object, all published and not hidden;
- `layout` is `scatter` or `rows`;
- `1 ≤ stars.two ≤ stars.three ≤ question_count`;
- feedback titles are 1–80 characters and the hint is 1–160;
- the prerequisite is published, isn't the level itself, and forms no cycle;
- every number from 1 to `range.max` has a published copy with audio (`NUMBER_AUDIO_MISSING` on `range.max`, plus one on `numbers.N` for each number without audio).

#### Scenario: Range out of bounds
- **WHEN** a publisher publishes a level with range 5–25
- **THEN** publish responds 422 with a field error on `range.max`

#### Scenario: Missing count audio
- **WHEN** Level 3 has range 11–20 and number 14 has never been published
- **THEN** publish responds 422 with `NUMBER_AUDIO_MISSING` on `range.max` and on `numbers.14`

#### Scenario: Opaque object picture
- **WHEN** an object's uploaded picture has no transparent pixel
- **THEN** publishing the object responds 422 `NOT_TRANSPARENT` on `image`

#### Scenario: Prerequisite cycle
- **WHEN** Level 1 requires Level 2 and a publisher publishes Level 2 requiring Level 1
- **THEN** publish responds 422 on `prerequisite_id`

### Requirement: Safe hiding and deletion
- Deleting an object referenced by any level draft or version SHALL respond `409 OBJECT_IN_USE`.
- Hiding an object SHALL respond `409 OBJECT_LAST_IN_LEVEL` when a published, visible level would be left without a published, visible object.
- Deleting a level SHALL be allowed only when it was never published and is no level's prerequisite. Otherwise it SHALL respond `409 LEVEL_IN_USE`.
- A hidden object SHALL stay resolvable for versions and sessions that reference it.

#### Scenario: Delete an object in use
- **WHEN** a publisher deletes "Apel", which Level 1 uses
- **THEN** the server responds 409 `OBJECT_IN_USE`

#### Scenario: Hide an object
- **WHEN** a publisher hides "Bebek", which Level 2 uses along with three other objects
- **THEN** Bebek is hidden, new Level 2 sessions skip it, and sessions in progress still show it

### Requirement: Level preview
`POST /admin/angka/levels/:id/preview {draft, seed}` SHALL validate the draft's shape. It SHALL then return the questions generated by `angkagen` for that seed, each with `count`, `object` (`name`, `question_text`, `image_url`, `question_audio_url`), `size` and `points`. Object media SHALL come from the object's draft when it has no published copy.

#### Scenario: Acak ulang
- **WHEN** the backoffice sends the same draft with a new seed
- **THEN** different questions are returned, and the same seed returns the same questions

### Requirement: Image transparency flag
Image uploads SHALL record `content_assets.has_alpha`. It SHALL be true when the image has an alpha channel and at least one pixel with alpha below 255, and false otherwise. Assets uploaded before this change keep `NULL`, which the transparency check accepts.

#### Scenario: Transparent PNG
- **WHEN** an editor uploads a 512 × 512 PNG with a transparent background
- **THEN** the asset is stored with `has_alpha: true`
